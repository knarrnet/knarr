## Track A — Security Hardening

### SEC-01: EventBus Thread Safety

**File:** `src/knarr/dht/eventbus.py`

`asyncio.Event.set()` was called from non-event-loop threads (BCW restructure added `bcw.watch_request`, `payment.received.*`, `payment.finalized.*` to the bus with cross-thread emit patterns). `asyncio.Event` is not thread-safe — calling `.set()` from a non-loop thread produces missed wakeups or crashes under specific scheduling.

Fix: `Subscriber._wake` signaled via `loop.call_soon_threadsafe(self._wake.set)`. `_loop` is the event loop captured at `EventBus.__init__` time. Fallback in `_wake_subscribers()` handles the case where the loop is not yet running.

### SEC-02: Netting Session Lock, TTL, and Sender Check

**File:** `src/knarr/commerce/handlers.py`

`_netting_sessions` was an unsynchronized closure dict shared between `handle_netting_proposal` and `handle_netting_acceptance`. Three separate vulnerabilities:

1. **Race condition:** Concurrent proposals for the same `netting_id` could corrupt the session store.
2. **No TTL:** Stale sessions accumulated indefinitely; a replayed proposal could reactivate a dead session.
3. **No sender check:** Any peer knowing a `netting_id` could burn the session (F-08, confirmed TP).

Fix: `asyncio.Lock` (`_netting_lock`) added with lazy initialization (F-09 — eager init binds to wrong event loop). TTL of 300s per entry. Sender verified inside the lock before popping. Both node IDs logged on sender mismatch: `expected={from_node[:16]} got={acceptance_from[:16]}`.

### SEC-03: SSRF — Broken IP Check + Hostname Bypass

**File:** `src/knarr/mail/handler.py`

The SSRF check in `_reassemble_spillover()` used a `try/except ValueError` pattern where the `except` block caught both hostname `ValueError`s and the deliberate `raise ValueError("private address")` — silently swallowing the block. Net result: only `localhost`, `127.0.0.1`, and `::1` were actually blocked. All RFC-1918 addresses (10.x, 172.16–31.x, 192.168.x), link-local addresses (169.254.x.x, fe80::/10), and arbitrary hostnames passed through.

Fix: Standalone host validation function with separate code paths for IP literals and hostnames. IP literal → check `is_private`, `is_loopback`, `is_link_local` — reject any match. Hostname → reject outright (sidecar addresses are always IPs). Port validated in range 1–65535.

### SEC-04: TLS Verification Disabled in Sidecar Fetch

**File:** `src/knarr/core/warehouse_manager.py`

Sidecar content fetch used `ssl.CERT_NONE`, disabling certificate verification and opening a full MITM surface. The SHA-256 content hash check provided partial mitigation (content substitution detected) but not connection-layer protection.

Fix: `ssl.CERT_REQUIRED` with system CA bundle. SHA-256 content hash check retained as defence-in-depth.

### SEC-05: Fee Payer Bypass When `node_address` Is Empty

**File:** `src/knarr/commerce/handlers.py`

The fee payer check `if node_address and parsed["fee_payer"] == node_address` short-circuits when `node_address` is `None` or `""`, bypassing validation entirely on unconfigured nodes.

Fix: Inverted guard — if `node_address` is not configured, reject the payment request fail-closed rather than bypassing the check.

### SEC-06: Unbounded In-Memory Caches

**File:** `src/knarr/dht/node.py`

Five dicts/sets in `DHTNode` were never evicted: `_admission_cache`, `_seen_messages`, `_seen_task_requests`, `_task_events`, `_task_results`. On a long-running node with sustained traffic these grow to OOM.

Fix: LRU eviction (evict oldest on insert when at cap) on dedup caches. TTL expiry on `_task_events` and `_task_results` (time-bounded by task lifecycle). Cap sizes config-driven with defaults (e.g., `_seen_messages` capped at 10,000 entries).

### SEC-07: Thread Pool and Storage Not Closed on Shutdown

**File:** `src/knarr/dht/node.py`

`ThreadPoolExecutor` was created at node init and never joined in `stop()`. `storage.close()` existed but was not called. In-flight handlers at shutdown were abandoned with potentially open transactions.

Fix: In `stop()`, after background tasks are cancelled: `executor.shutdown(wait=True)` then `storage.close()`. Order enforced: cancel tasks → join executor → close storage.

### SEC-08: Settlement Mail Failure → Ledger Divergence

**File:** `src/knarr/commerce/settlement_execution.py`

In `execute_settlement()`, the receipt was written to storage and a `settlement.accepted` bus event emitted before `send_mail_fn()` was called. If `send_mail_fn()` raised, the exception was logged as a warning and execution returned `receipt_id`. The local node had a persisted receipt; the peer never received the settle_request.

Fix: Receipt write moved to after a successful `send_mail_fn()` call. Notify attempted first — on failure, no state mutation occurs. Full context logged on failure (receipt_id, peer, timestamp) for manual reconciliation.

## Track B — BCW WebSocket Subscription (D-01)

**Files:** `src/knarr/plugins/10-bcw/handler.py`, `src/knarr/plugins/10-bcw/solana.py`

Replaced periodic polling with real-time Solana WebSocket subscriptions. `SolanaSubscriptionManager` manages account and transaction signature subscriptions for all watched addresses. Notifications route through a unified `_process_transfer` pipeline shared with the existing gap-recovery path.

Key behaviors:
- **Account subscriptions** (`accountSubscribe`) fire on any account state change; notification data decoded directly, updating the payment cursor.
- **Signature subscriptions** (`signatureSubscribe`) confirm specific transactions; matched against the pending signature store.
- **Gap recovery fallback:** `on_tick()` runs `getSignaturesForAddress` polling when WebSocket is disconnected, ensuring no payments missed during subscription outages.
- **`WatchStore` schema extension:** `correlation_id` field added to `bcw_watchlist`; propagated through the transfer classifier, receipt structure, and dedup path.
- **`pyproject.toml`:** `websockets` added as optional extra (`[bcw]`).

> **D-01 schema CR (non-blocking):** WS notification handlers emit thin `payment.received.{chain_id}` events; gap-recovery path emits the richer existing payment shape. CR filed for v0.50.0 normalization.

## Track C — Kademlia Structured Sweep (KAD-01, KAD-02)

### KAD-01: Bucket-by-Bucket Sweep via Plugin

**File:** `src/knarr/plugins/00-kademlia/handler.py`

Moved peer sweep from `node.py`'s O(n) `_peer_heartbeat_sweep()` to the kademlia plugin's `on_tick()` hook, implementing Kademlia §2.3 bucket-by-bucket traversal.

`_sweep_k_buckets()` iterates 8 buckets per tick, checking `bucket[0]` (Least Recently Seen per §2.3). `_is_well_covered()` uses routing-table fill (`filled_buckets >= 5`) to skip sweep on healthy tables. `inspect.isawaitable()` guard handles both sync and async peer-check callbacks. Eviction via `PluginContext.remove_peer`.

Net effect: sweep work amortized — constant-time per tick regardless of network size. `asyncio.gather()` holding the event loop 3–5s per cycle at high peer counts eliminated.

**PluginContext additions:** `remove_peer → storage.remove_peer`, `upsert_address → storage.upsert_address`, `push_to_peer → send_fn`. All three added to the factory path; legacy positional constructor unchanged.

> **Backward compatibility:** `_peer_heartbeat_sweep_loop` and `_peer_heartbeat_sweep` remain in `node.py` as fallback for nodes without the plugin. Will be removed when Phase D is confirmed stable (D-007-D CR open from v0.48.0).

### KAD-02: Bootstrap Peer Eviction

**File:** `src/knarr/dht/node.py`

`_evict_bootstrap_peers()` promotes bootstrap-only entries out of the routing table once real peers are found. Bootstrap peers that have never contributed to routing (no skill announcements, no active tasks) are pruned when the routing table reaches sufficient fill. Prevents bootstrap nodes from occupying routing slots that should go to capable peers.

## Track D — Bootstrap Resilience (D-02)

**File:** `src/knarr/dht/node.py`

Upon isolation recovery, the node re-joined using `self._bootstrap_peers` (runtime peer list) rather than the original configured peers. If the runtime list had decayed, rejoin failed silently or thrashed.

New state:
- `_initial_bootstrap_peers` — set once at `join()` from configured peers; never mutated.
- `_isolation_rejoin_backoff` / `_isolation_rejoin_last` — exponential backoff (doubles per attempt, capped at 300s) with jitter restored per B2 design.
- `_should_attempt_rejoin()` / `_record_rejoin_attempt()` / `_reset_rejoin_backoff()` — encapsulate rejoin timing logic.

Architectural split: `_peer_heartbeat_sweep_loop` no longer calls `_peer_heartbeat_sweep` directly. The sweep is the kademlia plugin's responsibility (KAD-01). The loop handles reconnection and routing-table recovery only.

`_self_populate_routing_table()` uses the defensive triple-getattr pattern for plugin lookup: graceful fallback if the kademlia plugin is absent or the registry API changes.

## Track E — Architecture (CARVE-01, CARVE-02)

### CARVE-01: NodeAPI Extraction

**File:** `src/knarr/dht/node.py` (dashboard accessor methods)

Status/dashboard API methods (`get_*` accessors used by `DashboardServer`) extracted from `DHTNode` into `NodeAPI`. `DHTNode` exposes `self.api = NodeAPI(...)` created in `__init__`; `DashboardServer` calls `node.api.get_*()`. 4-model panel (GPT-5.4, Gemini 3.1 Pro, Sonnet 4.6, Opus 4.6). 20 raw findings → 11 confirmed true positives, all fixed before promotion. 2 false positives. 7 informational or deferred.

| ID | Severity | Finding | Fix |

| F-01 | CRITICAL | WM internal signer fast path skipped Gate 1 signature verification — `ingest()` matched `verificationMethod` fragment without verifying the actual signature | Actual `verify_document()` call added to internal signer path |
| F-02 | HIGH | `_handle_settlement_confirmation` zeroed bilateral ledger unconditionally without cross-checking `amount_settled` against prior balance | Amount cross-check with 1% tolerance; mismatched amounts rejected |
| F-03 | HIGH | `request_task()` sync path accepted any signed `TaskResult` without verifying signer == `provider_node_id` | SHA-256 node ID binding check; wrong provider returns `status="failed", error.code="WRONG_PROVIDER"` |

| F-07 | HIGH | `handle_credit_note` applied refunds without verifying sender is the original provider | `provider_node_id` check against execution log |
| F-08 | HIGH | `handle_netting_acceptance` popped session before sender check — attacker could burn sessions blocking legitimate settlement | Peek-then-verify-then-pop within the same lock (SEC-02) |

## What was broken

v0.56.0 shipped a regression in the additive `TaskRequest` URI validator
introduced by the adversary #7+#8 hardening (Opus + GPT findings on URI
tautology and foreign `target_identity` auth bypass).

The validator called `registry.resolve(msg.target_identity)` on every
`TaskRequest` with a `target_identity` set. But `submit_async_task` at
`dht/node.py:1769` and `:3043` sets `target_identity = provider_node_id`
for all cross-node requests per the E-01 convention since v0.55.0. On
single-identity nodes the `IdentityRegistry._identities` dict is empty,
`resolve()` returned `None`, and the validator rejected with
`reason=authority_unknown_identity`.

Every cross-node skill call failed with `URI_MISMATCH`. The sender saw
`TaskResult(status="failed")` or a timeout.

Wave 1 missed the regression because the test fixture's `_make_node()`
never wired up `_identity_registry`. The validator's
`getattr(self, "_identity_registry", None)` fell back to `None` and the
`resolve()` branch was never exercised in unit tests.

**G-18 cross-machine cluster gate caught this on first use.** Loopback
testing passed; cross-machine test failed immediately. This is exactly
the integration layer the gate exists for.

## What the fix does

Adds a **self-target fast path** in `_validate_task_request_uri` at
`dht/node.py:4083-4088`. When `msg.target_identity == self.node_info.node_id`
(the legitimate case: a peer is calling a skill on this node), the validator
skips the `IdentityRegistry` lookup and accepts immediately — while still
enforcing that the URI authority, if present, matches this node's own
`node_id`.

```python
if msg.target_identity:
    if msg.target_identity == self.node_info.node_id:
        # Self-target fast path — we are the intended recipient.
        # Still enforce URI authority consistency.
        if authority and authority != self.node_info.node_id:
            reason = "authority_mismatch"
    else:
        # Foreign target — must be a locally-hosted multi-identity.
        registry = getattr(self, "_identity_registry", None)
        resolved = registry.resolve(msg.target_identity) if registry is not None else None
        if resolved is None:
            reason = "authority_unknown_identity"
        elif authority and authority != resolved.node_id:
            reason = "authority_mismatch"
```

Both adversary defenses are preserved:

- **Adversary #7 (Opus URI tautology):** URI authority is compared to
  `self.node_info.node_id` (self-target) or `resolved.node_id` (foreign
  target), never to the attacker-controlled `target_identity` field.
- **Adversary #8 (GPT foreign fallthrough):** when `target_identity` is
  foreign (not this node's own) and does not resolve to a locally-hosted
  identity, the validator still rejects with `authority_unknown_identity`.

## Regression tests added

Two new tests in `tests/unit/test_t2_01_taskrequest_uri_v56.py`:

- `test_validate_task_request_uri_accepts_self_target_happy_path` —
  closes the Wave 1 gap by exercising the fixture's node_id as both
  `target_identity` and URI authority. Would have caught the v0.56.0
  regression if it had existed.
- `test_validate_task_request_uri_rejects_foreign_unresolvable_target_identity` —
  pins the adversary #8 defense so future edits to the validator can't
  accidentally regress the foreign-target rejection path.

# Release Notes — v0.53.0 "Protocol Decoupling + Identity Realms"

**Date:** 2026-03-27
**Base:** v0.52.10

---

## Summary

Two structural problems solved: protocol/handler resource coupling (caused 10 hotfixes during exp-150) and single-identity-per-process scaling constraint. The node becomes a protocol router hosting N identities with isolated resources.

## Theme A — Protocol Decoupling

- **A-01:** Dual thread pool — `_protocol_pool` (8 threads) + `_handler_pool` (32 threads). Protocol operations (heartbeat sweep, peer get) run on dedicated pool. Configurable via `[node.pools]`.
- **A-02:** Two-tier EventBus — ScopedEventBus transparently routes protocol topics (`peer.*`, `node.*`, `security.*`) to protocol bus, identity topics to identity bus. Zero caller migration needed.
- **A-03:** IMPLICIT_HB configurable — `[node] implicit_hb_types` controls which message types trigger liveness tracking. Default: Heartbeat, Announce, Query.
- **A-04:** Firewall gateway IP exemption — `[firewall] gateway_exempt` bypasses L1 rate limiting for Docker bridge gateways.
- **A-05:** Prune timeout multiplier — `[node] prune_timeout_multiplier` operator lever for routed topologies (Docker: 3.0).
- **A-06:** Write queue event-based — `asyncio.Event` replaces `sleep(0.01)` polling. Zero wakeups at idle.
- **A-07:** KAD post-promotion staggered across 3 ticks (self-lookup, refresh, republish).

## Theme B — Observability

- **B-02:** EventBus metrics — `ring_fill_pct`, `events_dropped_count`, `deferred_queue_depth`, `subscriber_count`. Logged when >50% full.
- **B-03:** Pool metrics — `active_workers`, `queue_depth`, `peak_queue_depth` via TrackedThreadPool.
- **B-04:** `GET /api/metrics` — aggregated bus, pool, cache, and identity stats.

## Theme C — Exp-150 Fixes

- **C-03/C-04/C-05:** Groups HTTPS, UPnP, punchhole startup wrapped in `asyncio.to_thread`.
- **C-06:** PluginContext `get_economy_stats()` — plugins call storage directly instead of HTTP.

## Theme E — Identity Realms

- **E-01:** `target_identity` field on TaskRequest/MailPullReq, `target_node_id` on PluginMessage.
- **E-02:** Connection handler identity demux — `_resolve_target_identity()` scopes execution to target identity's storage/signing key.
- **E-03:** `IdentityRegistry` + `Identity` classes in `dht/identities.py`. Skill-to-identity routing.
- **E-04:** `[identities.*]` config parser. No config = single identity (backward compatible).
- **E-05:** Per-identity storage — separate SQLite DB per identity. `node_id = SHA256(public_key)`.
- **E-06:** Per-identity skill announcements with identity-derived wallet/encryption key.
- **E-07:** Multi-identity launcher — creates per-identity storage/keys/bus, populates skill routing.

## Adversary Fixes (13 applied)

3 fixed during review (demux wiring, node_id derivation, public_key_hex), 10 from adjudication (skill routing, announce scoping, ScopedEventBus wiring, Executor inheritance, subscriber buffering, prune bound, protocol pool submit, submit failure cleanup, cancel cleanup, unsubscribe).

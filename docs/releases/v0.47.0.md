## Track A — Core Bug Fixes

### A1: `self._debug` Init Miss — Settlement Broken (BR-SETTLE-001)

`DHTNode.__init__` assigned per-module debug flags (`_enc_debug`, `_bus_debug`, etc.) but never set `self._debug`. Settlement threshold handlers at two sites used `if self._debug:` without a guard, raising `AttributeError` on every tick. Manifested as 690 exceptions and zero automatic settlements in a 10.8-hour cluster run.

**Fix:** `self._debug = self._config.get("node", {}).get("debug", False)` added in `__init__`. Added `exc_info=True` to the bare `except Exception` in `_settlement_consumer_tick` for better diagnostics.

### A2: `store_skill` Demotes `is_own` Flag (BR-is_own)

`ON CONFLICT` clause used `is_own=excluded.is_own`. DHT re-propagation of remote skill announcements overwrote the flag to 0, demoting the node's own skills. 23 of 177 skills demoted in a single run; demoted skills are excluded from direct-execution scoring.

**Fix:** `is_own=MAX(is_own, excluded.is_own)` — preserves the flag if it was ever set to 1 locally.

### A3: Sequential Peer Sweep Blocks Event Loop (BR-PEER-001)

`_peer_heartbeat_sweep` awaited each peer sequentially. At 49 peers × ~300ms RTT = 14.7s, exceeding `PEER_HEARTBEAT_SWEEP_TIMEOUT` (10s). Generated 515 `PEER_SWEEP_TIMEOUT` events in 10.8h; late heartbeats caused false peer drops.

**Fix:** Parallelized with `asyncio.gather(*[_hb_one(p) for p in batch], return_exceptions=True)` behind `asyncio.Semaphore(10)`. New `_hb_one` helper extracts the per-peer logic. Concurrency bounded to prevent thundering herd.

### A4: `tab_reminder` Handler Missing — Credit Loop Dead (BR-MAIL-001)

`make_commerce_handlers()` registered four commerce message types; `knarr/commerce/tab_reminder` was absent. 488 tab reminder messages were logged as unhandled and dropped in 10.8h, silently stalling the credit-utilization notification loop.

**Fix:** Added `handle_tab_reminder` in `commerce/handlers.py`. Validates the body against the existing `validate_tab_reminder` schema, logs at INFO, no side effects. Adversary gate added range check for `utilization_pct` (must be 0–100) to schema validation (TP-5).

### A5: `MAIL_FLUSH_SKIP` Emits No Bus Event (BR-MAIL-002)

`mail/sync.py` logged a warning on flush skip (605 occurrences in 10.8h) but emitted nothing to the event bus. Monitoring had no visibility into flush suppression.

**Fix:** After the existing warning, emits `_bus.emit("mail.flush_skip", to_node=to_node[:16])` using the `getattr(self._node, 'bus', None)` pattern from `cleanup()`.

## Track B — Features

### B1: `GET /api/settlements` Cockpit Endpoint (DASH-01)

`settlement_queue` returned 0 rows to `collect.py` in the 100-node experiment despite 209 settlements reconstructed from logs. Investigation: the endpoint did not exist; `collect.py` was receiving 404 silently. Added `GET /api/settlements` with `status`, `limit`, and `offset` query parameters. Returns `{"settlements": [...], "total": N}` with column names matching `settlement_queue` exactly; `body` is parsed from JSON text and returned as an object.

Adversary gate hardened the endpoint: `limit` is clamped to `[1, 500]` (TP-1), `offset` floored to 0 (TP-3), ValueError on bad params returns 400 (TP-2), DB errors return a generic 500 with no raw exception text.

### B2: Bootstrap Isolation Warning (P-026)

Empty bootstrap peers check emitted a terse or missing log message. Improved to:

> "No bootstrap peers configured — this node is isolated from the network. Add [network] bootstrap = [...] to knarr.toml or use --bootstrap flag"

Adversary gate corrected the config key text from `bootstrap_peers` to `[network] bootstrap` (TP-4).

### B3: BCW Amount Int Cast (E-033)

`float(event.get("amount", 0))` on lamport values. IEEE-754 double precision is insufficient for u64 lamport amounts above ~9M KNARR in a single payment. Changed to `int()` at each call site in the BCW handler. Adversary gate added a non-positive amount guard (TP-6): amounts ≤ 0 log a warning and return early before reaching `_credit_ledger`.

## Track C — Watchman Fixes (Forseti scope)

### A11: `cmd_upgrade` Kills Newly Spawned Node on Windows

Watchman supervisor killed the newly launched node process immediately after upgrade on Windows due to process group membership. Fixed in `watchman/supervisor.py` and `watchman/upgrader.py`.

### A12: `cmd_status` PID Liveness Broken on Windows

`cmd_status` reported the node as running when it was not, due to Windows process liveness check semantics. Fixed in `watchman/main.py`.

### O-031: Path Traversal in `staging_dir`

Unsanitized `staging_dir` path in `watchman/upgrader.py` could be escaped via `../` sequences. Hardened with path normalization and containment check.

### O-032: Tar Member Path Escape After Prefix Strip

After stripping the archive prefix, member paths were not re-validated. A crafted archive could write files outside the staging directory. Fixed in `watchman/plugin_manager.py`.

### O-033: Checksum Verification Skipped on Wheel-First Archive

When a wheel file appeared before `checksums.txt` in archive iteration order, the checksum step was skipped silently. Fixed in `watchman/upgrader.py` to require checksum presence before any extraction.

### O-034: Plugin Name TOML Injection

Plugin names were interpolated into TOML strings without sanitization, enabling injection via crafted plugin names. Fixed in `watchman/plugin_manager.py`.

### C1: Address Book Weighting in `_select_execute_provider`

`_select_execute_provider` now applies explicit-tier address book weights when scoring execution candidates, enabling operator-configured preferred-provider routing.

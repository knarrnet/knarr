# Release Notes — v0.42.0 "Valholl" (Warehouse Manager Activation + Conversion Boundary)

**Date:** 2026-03-10
**Branch:** `feature/v0.42.0`
**Base:** v0.41.0

---

## Summary

Valholl activates the Warehouse Manager — a 5-gate document validation pipeline for all inbound commerce mail — and wires the token/credit conversion boundary at deposit and settlement. Four-model dev panel (Gemini, GPT-5.4, Sonnet, Qwen), three-judge panel (GPT-5.4, Gemini, Opus), five-model adversary panel (GPT-5.4, Sonnet, Opus, Gemini, Qwen — 28 exploit tests) identified 16 deduplicated findings. 8 fixed, 3 accepted, 2 deferred, 2 rejected as false positives. Cluster gate tested (exp9, 3-node + bootstrap).

## Breaking Changes

None. WM is opt-in via `warehouse_manager.enabled = true` in config. Nodes without this setting behave identically to v0.41.0. The `_chain_topic` function now returns `solana_devnet` and `solana_testnet` instead of `solana` for devnet/testnet chains — existing internal subscribers use glob patterns and are unaffected.

## New: Warehouse Manager Activation (Track A)

The Warehouse Manager validates all inbound commerce documents through a 5-gate pipeline before they reach handlers. Previously implemented but never wired into the live system.

### A1: Quarantine Storage

Five methods added to `dht/storage.py`: `quarantine_store`, `quarantine_get`, `quarantine_update_status`, `quarantine_list_pending`, `quarantine_list_by_status`. Documents that fail validation are persisted in the `dmz_quarantine` table for review or retry.

### A2: WM Instantiation

When `warehouse_manager.enabled = true`, `DHTNode.__init__()` creates the WM with:
- 6 identity fragments: `node_id`, `public_key_hex`, DID base, `#key-1`, `#cockpit-1`, `#thrall-1`
- Internal signer keys collected from thrall identity and cockpit signing key (when present)
- Settlement document types auto-promoted via `setdefault()` — only injected if user hasn't configured explicit rules

### A3: Dispatch Gate

Single gate in `_dispatch_system_item()` (mail/sync.py):
- Commerce documents (`knarr/commerce/*`) always route through WM
- Non-commerce system messages only route through WM if they carry a `proof` field
- Unsigned system messages (task results, asset fetch) bypass WM — authenticated at transport layer
- Settlement envelopes unwrapped before WM ingest to validate the inner document, not the wrapper
- Held/rejected documents logged and dropped; promoted documents proceed to handlers

### A4: Async Bridge

`_wm_ingest()` on DHTNode wraps the synchronous WM `ingest()` in a 5-second timeout via `asyncio.wait_for`. Returns rejected result on timeout. Applies node-level countersigning when WM flags `needs_countersign=True`.

### A5: Startup Recovery

After plugin subscriptions are active, re-emits `wm.held.*` bus events for quarantined documents still in pending state. Wrapped in try/except so storage failures during startup don't crash the node. No-op when WM is disabled.

### A6: Plugin Document Countersigning

Internal signer detection via `verificationMethod` DID fragment only (self-asserted proof fields like `publicKeyHex` removed as spoofable). When WM detects a document from an internal signer (thrall, cockpit), gates 1/2/5 are skipped, gates 3/4 run, and `needs_countersign=True` is flagged. The async bridge then adds the node's primary key (`#key-1`) as an additional signer. Fixes the exp8 settlement bug where plugin-generated documents lacked node-level authorization.

## New: Conversion Boundary + Mainnet Wiring (Track B)

### B1: Conversion Wiring

Token/credit conversion at both economic boundaries:
- **Deposit:** BCW plugin converts received token amount to credits via `token_to_credits()` with configurable conversion rate, credits payer's ledger
- **Settlement:** `execute_settlement()` converts credit amount to token amount via `credits_to_token()` before on-chain send
- **Rate source:** `economy_config` field added to `PluginContext` so BCW reads the same global `[economy]` config as settlement (prevents config arbitrage)
- Default rate warning logged at startup when `conversion_rate` is not configured

### B2: Mainnet Chain ID

`solana-mainnet` added to supported chain IDs. Requires explicit `rpc_url` in config (no hardcoded default). Devnet and testnet retain default RPC URLs. Per-chain event topics: `payment.finalized.solana`, `payment.finalized.solana_devnet`, `payment.finalized.solana_testnet`.

### B3: SOL Gas Alerting

BCW plugin periodically checks master wallet SOL balance via RPC `getBalance` (every 300s). If below configurable threshold (`sol_min_balance`, default 0.01 SOL), emits `wallet.sol_low` bus event and logs warning.

### B4: x402 Refund Path

When a paid skill execution fails, a credit note is issued to refund the payer:
- Refactored from inline closure to class method `_issue_x402_refund()` on CockpitServer
- Charged amount converted from tokens to credits before refund (using global conversion rate)
- `payer_node_id` resolved to `peer_public_key` via `_resolve_public_key()` before ledger update
- Covers both local and remote execution failure paths

### B5: Payment Receipt Storage

`check_payment_receipt()` and `store_payment_receipt()` added to `dht/storage.py`. Used by x402 payment validation to prevent duplicate charges. Idempotent writes via `INSERT OR IGNORE`.

### Gate 2 Hotfix

Settlement documents use `peer_public_key` in the `counterparty` field, but the original identity fragments only included `node_id` (SHA256 of pubkey). Gate 2 rejected all settlements. Fixed by adding `_public_key_hex` to the identity fragments list (1 LOC).

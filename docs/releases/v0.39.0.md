# Release Notes — v0.39.0 "Midgard" (Economy + Cockpit Wiring, Adversary-Hardened)

**Date:** 2026-03-07
**Branch:** `feature/v0.39.0`
**Status:** Cluster gate pending

---

## Summary

Midgard wires real money into the protocol: the x402 payment gate verifies Solana transactions on paid skill exposures, meter-based rate limiting protects compute, and the bounty hold lifecycle moves to bus events. Five-model adversary panel (Opus, Sonnet, Gemini, GPT, Qwen — 141 attack tests) identified 29 vulnerabilities, all mitigated in the fix pass.

## Breaking Changes

- **`KNARR_DECIMALS` 6 → 9** — constant changed in `core/constants.py`. External consumers reading this value will get a different result. Affects any token amount formatting or display logic.
- **`/api/skills/{name}/schema` endpoint removed** — schemas now served through punchhole cache only. Third-party integrations using direct schema access must update.
- **Netting validators require `token` field** — schema tightening via `_validate_token()`. Existing netting documents without a `token` field will fail validation. Peers sending old-format netting docs must update.

## New Module

### x402 Payment Gate (`src/knarr/commerce/x402.py`)
Storefront payment verification for paid skill exposures. Parses Solana legacy transactions, verifies SPL Token `TransferChecked` instructions against expected amount, asset mint, and destination.

Security controls:
- **Single-instruction enforcement** — rejects multi-instruction transactions (prevents drain instruction smuggling)
- **Fee payer safety** — node address must not appear as fee payer or in instruction account list
- **Size limit** — 1232 bytes (Solana max), trailing bytes rejected
- **Fail-closed config** — empty `payment_asset` or `payment_address` returns 500, not a silent bypass
- **Two-layer replay protection** — in-memory TTL cache (120s) + persistent `payment_receipts` table in SQLite

## Wiring Changes

### Admission Pipeline
`run_admission()` + `_admission_cache` + `_build_pricing_config()` helper wired into node.py. Admission pipeline module (`admission_pipeline.py`) predates v0.39.0; what's new is the node-level integration and meter field additions.

### Token Symbol
`_token_symbol` wired into node and commerce handlers. Credit notes and handler logs now include token symbol. Multi-token groundwork.

### `/api/logs` Endpoint
New operator capability. RingBufferHandler with 1000-entry ring buffer, Bearer auth required. Exposes structured log access via cockpit.

### Dashboard Poll Refresh Guard
Dashboard no longer refreshes while the user is typing in form fields. Prevents input loss during auto-refresh cycles.

## Schema Changes

### Migration: `v0_39_0.sql`

```sql
ALTER TABLE ledger ADD COLUMN held_balance REAL DEFAULT 0.0;

CREATE TABLE IF NOT EXISTS meter (
    actor TEXT NOT NULL, skill TEXT NOT NULL, qualifier TEXT DEFAULT '',
    count INTEGER DEFAULT 0, first_at REAL, last_at REAL,
    window_seconds REAL DEFAULT 0,
    PRIMARY KEY (actor, skill, qualifier)
);

DROP TABLE IF EXISTS settlement_state;

CREATE TABLE IF NOT EXISTS payment_receipts (
    tx_digest TEXT PRIMARY KEY, amount INTEGER NOT NULL,
    asset TEXT NOT NULL, destination TEXT NOT NULL, verified_at REAL NOT NULL
);
```

- `held_balance` — funds held pending bounty quality review
- `meter` — per-actor, per-skill execution counters with time windows
- `payment_receipts` — persistent x402 replay dedup (survives restart)
- `settlement_state` dropped (superseded by netting lifecycle from v0.38)

## Bounty Hold Lifecycle

**Design change:** Quality gate orchestration removed from node.py. Protocol now holds funds and emits `bounty.pending_review` bus event with full context (task_id, skill, peer, amount, output, quality_gate skill name). Plugin subscribes to the event and calls `release_held()` or `return_held()` to resolve.

This follows the standing principle: protocol supplies primitives, agents compose flows.

## Commerce Hardening

- **HTTPS-only RPC** — remote Solana RPC endpoints must use HTTPS. HTTP allowed only for localhost/127.0.0.1/::1 (local devnet)
- **Bounty decay clamp** — `bounty_decay` config clamped to `(0, 1.0]`. Prevents collapse-to-zero (decay=0) or exponential payout inflation (decay>1)
- **Credit note cap** — refund cap tightened from 2x to 1x original price
- **Circuit breaker identity** — `mail.peer_circuit_open` bus event now includes `identity=peer` field

| Model | Tests | Findings |

All 5 panels converged on the x402 multi-instruction smuggling vulnerability (CRITICAL). 29 total vulnerabilities mitigated. Grok and DeepSeek dropped (weak output / API error).

### Accepted Findings (fixed)
- F-001: x402 multi-instruction smuggling + fee payer bypass (CRITICAL)
- F-002: Empty asset/destination skips verification (HIGH)
- F-003: Replay protection TTL-only, no persistence (HIGH)
- F-004: Trailing bytes + oversized transactions accepted (MEDIUM)
- F-005: HTTP RPC for remote settlement endpoints (HIGH)
- F-007: Bounty decay 0/above-1 manipulation (HIGH)
- Credit note 2x cap too generous (HIGH)
- `token_instruction` NameError in x402 verifier (BUG)

### Not Fixed (by design)
- F-006: Admission gate free pass for bounties/tit-for-tat — no monetary exposure, rate limits handle compute abuse
- F-008: Netting unknown token symbol — MEDIUM, requires token registry wiring into pure schema validators (future sprint)
- F-009: Bounty hold lifecycle unwired — fixed via bus.emit pattern (see above)

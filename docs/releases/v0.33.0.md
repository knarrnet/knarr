# v0.33.0 — Build the Machine

Released: 2026-03-01

## Summary

EventBus infrastructure, economy hardening from 7-model adversarial audit, mail delivery resilience.

## New Features

### EventBus
- Ring buffer with topic-based subscriptions
- Configurable size (16–65536 entries)
- Events emitted for: task lifecycle, credit changes, receipts, firewall actions, mail delivery, security
- Plugin subscription via `node.bus.subscribe(pattern)`

### Economy Hardening
- Atomic refund cap — single SQL UPDATE with 2x ceiling check (closes TOCTOU race)
- Sender identity verification on credit notes and refund requests
- `math.isfinite()` validation on all economy config values
- Cumulative refund tracking per task_id with `refund_total` column

### Mail Resilience
- Self-pruning guard — node no longer removes itself from peer table
- Stuck outbox recovery — `revert_stale_sending()` in cleanup cycle with retry cap (5)
- `retry_count` column now incremented on every delivery failure
- Bus events: `mail.delivery_failed`, `mail.outbox_stuck`, `mail.outbox_expired`

## Security Fixes (Adversarial Audit)

20 findings from 7-model attack panel (3 critical, 10 high, 7 medium):

- **TOCTOU refund race** — non-atomic check-then-update allowed concurrent credit notes to bypass 2x cap
- **Missing method** — `get_ledger_entry` called but didn't exist; replaced with `get_ledger_balance`
- **Balance inversion** — consumer credit formula used addition instead of subtraction
- **NULL sender bypass** — empty `from_node` or `requester_node_id` skipped identity checks
- **Dead EventBus subscriber** — `_wake.set()` on closed event could crash emit loop
- **Unbounded config** — `event_bus_size`, `max_queue_depth`, `min_peers` accepted negative/zero values
- **LIKE injection** — `has_pending_settlement` used unescaped LIKE pattern

## Migration

SQL migration `v0_33_0.sql` adds `refund_total` column to `execution_log`. Applied automatically on node start.

## Dependencies

No new dependencies. Python >=3.11, PyNaCl, cryptography.

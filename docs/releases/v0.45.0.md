# Release Notes — v0.45.0 "Stability"

**Date:** 2026-03-13
**Branch:** `feature/v0.45.0`
**Base:** v0.44.0

---

## Summary

Stability sprint: security and correctness fixes across settlement, BCW, and mail layers (Track A), plus performance and network-health fixes to the DHT and gossip layers (Track B). Fixes the WM Gate 1 key registration bug that silently blocked all settlement (E-031), adds forced local routing for knarr-mail (M-022), hardens BCW against lookalike-token attacks (ADV-7), and ships the settlement cadence guard (E-025). Track B delivers bootstrap jitter + DHT re-join (P-024/P-023), peer-sweep batch cap (P-025), and D-007 Phase C gossip suppression. Four-model dev panel, three-judge panel, adversary review, 100-node cluster gate.

## Breaking Changes

None.

## Track A — Security & Correctness

### A1: WM Gate 1 — Node Key-1 Registration (E-031)

`WarehouseManager` now receives the node's own primary verify key (`#key-1`) in `internal_signer_keys`. Previously only `thrall-1` and `cockpit-1` were registered; settlement documents signed by the node failed Gate 1 validation. Zero `WM_REJECTED` events in the cluster gate.

### A2: knarr-mail Forced Local Routing (M-022)

`_select_execute_provider()` now returns the local handler early when the skill is `knarr-mail`. Remote workers cannot perform external mail delivery; previously they were selected and returned 409 errors. Confirmed 409s dropped to zero after startup burst in cluster gate.

### A3: BCW Mint/Denom Validation (ADV-7)

`_handle_payment_finalized()` now validates `event["mint"]` against the configured `KNARR_MINT` address before calling `_credit_ledger`. Rejects deposits from lookalike SPL tokens. Companion fix: `TransferEvent` gains a `mint_address` field (populated by `solana.py`), and `_process_transfer` emits it in `common_fields` so the mint is available to the handler.

### A4: Settlement Cadence Guard (E-025)

New `settlement_cadence` table tracks last settlement timestamp per bilateral pair. `_handle_settlement_soft_threshold` guards against spam settlement: skips initiation if the interval since the last settlement is below `economy.settlement_min_interval_seconds` (default 86400s). Migration: `dht/migrations/v0_45_0.sql`.

### A5: BCW Lamport Normalization (ADV-6)

Raw lamport amounts are now divided by `10 ** KNARR_DECIMALS` (9) before passing to `token_to_credits()`. Previously raw amounts were used directly — a 1e9 overstatement for every deposit.

### A7: BCW Silent Failure on Invalid Chain ID (E-028)

BCW plugin now detects misconfigured chain IDs at startup: if `_enabled` is True but `_solana_modules` is empty after the chains loop, sets `_enabled = False` and logs a warning with the offending chain_id. Eliminates the silent no-op that appeared healthy but processed nothing.

### A8: async_jobs Failed-Job Retry Block (M-023)

New `purge_stale_failed_jobs(grace_seconds=300)` method in `Storage`. Called at job submission time to clear stale `failed` rows that were blocking retries.

### A9: Mail Hard-Block False ACK Logging (M-024)

When a peer's credit balance is below the hard limit, the mail sync engine now logs a `MAIL_HARD_BLOCK` warning (from=, item=, balance=, limit=) on both push and pull paths before continuing. The confirmed ACK is intentionally preserved — changing it would allow threshold probing. Also emits a `credit.sanctioned` bus event.

## Track B — Performance & Stability

### B1+B2: Bootstrap Jitter + DHT Re-join (P-024, P-023)

**B1:** `join()` now starts with `asyncio.sleep(random.uniform(0, 30))`. Staggers simultaneous startup of all nodes against bootstrap.

**B2:** `_peer_heartbeat_sweep_loop` tracks `_isolation_since` timestamp. When a node has been isolated (peer_count < 2) for more than 300 seconds, it triggers a re-join. Previously re-join only fired at peer_count == 0; nodes stuck at 1 never recovered.

### B3: Peer-Sweep Batch Cap (P-025)

`_peer_heartbeat_sweep()` now processes at most `SWEEP_BATCH_SIZE = 50` peers per cycle, using a rotating `_sweep_offset`. Previously all peers were processed in a single synchronous pass — at 100+ peers this caused 10s+ asyncio blocking.

### B4: D-007 Phase C — Gossip Suppression

`on_outbound()` in the Kademlia plugin now returns `False` for own-announce + full mode + public visibility, skipping the redundant `_put_provider_to_closest` gossip blast. Reduces network chatter on large clusters.

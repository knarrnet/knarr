# v0.56.0 — Transport Identity Binding

## Summary

v0.56.0 ships transport-layer identity binding on top of v0.55.0's security foundation. Minimal TOFU cert pinning binds peer cert fingerprints to node_ids on first contact. The P-01 default-deny ACL closes a default-grant footgun. Commerce chain URI addressability lands across the seven remaining tables. The exp-201 experiment gets unblocked via `query_plugin` hoist and PREREQ-01 heartbeat epoch bridge. Five debt items Patrick pulled from "defer and forget" ship cleanly.

One scope amendment landed late: a `samples` field on `SkillSheet` carrying Argus-style Ed25519-signed quality evidence for downstream discovery clients.

## ⚠ BREAKING CHANGE — Default-deny ACL on punchhole frontend (C-02)

**Impact:** Operators whose nodes serve punchhole cache objects to unknown requesters will see requests rejected instead of implicitly granted.

**What changed:** Previously, when a requester's `node_id` did not appear in the backend's ACL map, the frontend defaulted the tier to `"all_signed"` and served the cache object to any signed peer. This was a default-grant security posture — any signed requester on the network got baseline access without the operator opting in.

v0.56.0 changes the default to **deny**. Unknown requesters are rejected with an INFO log entry naming the reason:

```
PUNCHHOLE_ACL_DENY node_id=<id> reason=unknown_and_no_public_signed_tier
```

Operators can grep the logs for this message to identify which peers are being rejected and decide whether to grant them access explicitly.

### Operator mitigation — how to restore access for a specific peer

The ACL map in v0.56.0 is built from three runtime sources by `punchhole-backend`:
1. **`peer`** — nodes with an active bilateral ledger entry
2. **`known_hosts`** — nodes in the local address book with `tier = 'explicit'`
3. **`trusted`** — nodes listed in `trusted_nodes = [...]` in the exposure schema

To restore the previous "baseline access for this specific peer" behavior, add the peer's full node_id (64-char hex) to the `trusted_nodes` array in your exposure schema TOML:

```toml
# exposure_schema.toml or equivalent
trusted_nodes = [
    "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
]
```

After the backend reloads, the listed peers are pushed to the frontend ACL map with tier `trusted`. Object-level `access = "trusted"` entries in the schema then serve them.

Alternatively, establish a bilateral ledger relationship with the peer (makes them a `peer`-tier node) or add them to known_hosts with `tier = 'explicit'`.

**Note:** the sprint brief originally referenced a `public_signed` ACL tier as the operator escape hatch. v0.56.0 uses the existing `trusted_nodes` mechanism instead — functionally equivalent, no new config schema needed. If you were expecting `public_signed`, use `trusted_nodes` instead.

### Why hard cutover, no config knob

Patrick's direction: shipping a permissive default with a backward-compat opt-out knob is a footgun operators won't flip until after an incident. The team network has no external peers today; ARIA adversarial exposure is imminent. Default-deny ships without a backward-compat escape hatch so the ACL map becomes the explicit, auditable source of truth from v0.56.0 forward.

## Shipped items

### Section 1 — exp-201 Critical Path Unblockers

**T1-01: `query_plugin` hoist to DHTNode + `current_identity_name` helper** (~100 LOC)

`query_plugin` hoisted from `PluginContext` to `DHTNode` so skill handlers can call `NODE.query_plugin(...)` directly, not just plugins. `PluginContext.query_plugin` is a thin delegation shim — existing plugin callers unchanged. `PluginContext.current_identity_name()` helper returns the scoped identity name (or `None` in router context) so plugins can query per-identity state without importing core contextvar internals.

**Files:** `src/knarr/dht/node.py`, `src/knarr/dht/plugins.py`

**T1-02: PREREQ-01 heartbeat epoch bridge** (~80 LOC)

The `punchhole_epoch` field on the Heartbeat dataclass (shipped empty-default in v0.55.0) is now populated from the live backend counter at all 4 Heartbeat construction sites in `dht/node.py`. Remote nodes receive epoch increments and can trigger targeted re-crawls of specific peers instead of periodic full crawls. Unblocks the exp-201 indexer's event-driven re-crawl design.

**Files:** `src/knarr/dht/node.py`, `src/knarr/plugins/09-punchhole-backend/handler.py`

### Section 2 — Transport Identity Binding

**C-01: Minimal TOFU cert pinning + hybrid AAD binding + recovery CLI** (~100 LOC)

Trust-On-First-Use cert fingerprint pinning. On the first successful signature-verified connection from a peer, the peer's TLS cert fingerprint is stored keyed by `node_id`. On subsequent contacts, a fingerprint mismatch triggers a `security.cert_pinning_mismatch` bus event and rejects the connection with `CertPinMismatchError`. Bidirectional: server-side (`_handle_connection`) and client-side (`request_response` + pool `_try_send`) extract the fingerprint at handshake time and attach to the verified message.

Additionally: `core/crypto.hybrid_encrypt` / `hybrid_decrypt` now bind the canonicalized sorted recipient list into the AES-GCM AAD, preventing reorder/tamper attacks on the wrapped key set. New `knarr peer forget-fingerprint <node_id>` CLI command clears stored fingerprints — use this after a legitimate cert rotation.

**Honest framing:** TOFU does NOT protect against a MITM already in position at first contact. The ARIA claim is "cert fingerprint pinned on first contact, mismatch on subsequent contacts is rejected" — NOT "cert identity cryptographically verified." First-contact MITM requires DHT compromise, which is a separate attack class addressed by Ed25519 announcement signatures.

Full PKI (rotation, revocation, chain validation beyond `CERT_NONE`) is deferred to a dedicated TLS hardening sprint post-v0.56.0.

**Files:** `src/knarr/dht/node.py`, `src/knarr/dht/pool.py`, `src/knarr/dht/protocol.py`, `src/knarr/dht/storage.py`, `src/knarr/core/crypto.py`, `src/knarr/cli/main.py`

**C-02: P-01 auth gate default-deny ACL** (~30 LOC)

See the breaking change section above. `plugins/08-punchhole-frontend/handler.py` default fallback from `"all_signed"` to `""` (deny) when an unknown node_id requests a cached object.

**Files:** `src/knarr/plugins/08-punchhole-frontend/handler.py`

### Section 3 — Commerce Chain URI Addressability

**T2-01: Additive URI field on TaskRequest** (~40 LOC)

`TaskRequest` gains an optional `uri: str = ""` field. v0.56.0+ providers populate it with `knarr://{provider}/s/{skill}@{version}`. Receiver-side validation (in `dht/node.py` task dispatch) uses `parse_knarr_uri + skill-match policy check` — rejects cross-field mismatches with a `security.uri_mismatch` bus event naming the specific failure (`invalid_uri`, `bad_selector`, `skill_mismatch`, `authority_mismatch`).

v0.55.0 clients continue working: empty URI bypasses validation and routes via the flat `skill_name` field. Migration horizon (Phase 2: warn on missing, Phase 3: require) filed as `thing/bugs/CR-taskrequest-uri-migration-horizon.md` for v0.57.0+.

**Files:** `src/knarr/core/messages.py`, `src/knarr/dht/node.py`

**T2-02: URI column expansion across commerce schema** (~80 LOC)

Seven tables gain a `uri TEXT NOT NULL DEFAULT ''` column + index: `skills`, `tasks`, `execution_log`, `async_jobs`, `mail_inbox`, `mail_outbox`, `settlement_queue`. Existing rows populated via migration `UPDATE` statements using templates derived from existing columns. Storage helpers updated to populate the URI on new inserts.

**Files:** `src/knarr/migrations/v0_56_0.sql`, `src/knarr/dht/storage.py`, `src/knarr/commerce/netting.py`

### Section 5 — Node Setup Ergonomics

**T2-08: Plugin loader package-path fallback** (~35 LOC)

Built-in plugins at `src/knarr/plugins/*` are now auto-discoverable on fresh node setup without manual symlinking. Plugins with missing required config are skipped with a WARNING and other plugins continue loading.

### Scope amendment — SkillSheet samples field

**`samples: Optional[List[Dict]] = None` on SkillSheet** (~160 LOC)

Landed late in assembly to support the Argus-style quality-rating workflow in exp-201. `SkillSheet` gains an optional `samples` field carrying Ed25519-signed quality evidence records. Validation block in `core/validation.py` enforces schema shape (required sub-fields, verdict whitelist, hex regex on rater keys, per-entry + total size caps) without verifying the cryptographic signatures. Consumer-side `verify_skill_sample(sample, rater_pubkey=None)` helper in `core/crypto.py` performs Ed25519 signature verification + `rater_node_id == sha256(rater_pubkey)` consistency check. Trust list is a client-side concern (filed as `CR-rater-trust-list` for v0.57.0).

Size handling: `MAX_SAMPLES_SIZE = 32768` (32 KB total), `MAX_SAMPLES_ENTRIES = 10`, `MAX_SAMPLE_ENTRY_SIZE = 3200`. Samples excluded from the 4 KB base skill-sheet cap, mirroring the existing `input_schema_full` exclusion.

**Files:** `src/knarr/core/models.py`, `src/knarr/core/validation.py`, `src/knarr/core/crypto.py`

## Known limitations

- **Cert pinning is TOFU, not PKI.** A MITM in position at first contact with a new peer will pin their own fingerprint as legitimate. Use the `knarr peer forget-fingerprint <node_id>` CLI command after any legitimate cert rotation. Full PKI extension filed as `SPEC-tls-cert-pinning-pki.md` for a future dedicated TLS hardening sprint.

- **Samples field has no consumer trust list yet.** v0.56.0 ships the `samples` field and `verify_skill_sample()` helper but defers the client-side rater trust list config schema to v0.57.0 (`CR-rater-trust-list`). Consumers who want to act on rating evidence must maintain their own trust list mapping rater_node_id → rater_pubkey until the operator-facing config lands.

- **v0.55.0 nodes drop samples on re-emission.** When a v0.55.0 node receives an Announce with the samples field and later re-announces (gossip republish, KAD provider republish), the `SkillSheet.from_dict → to_dict` path drops the field because the v0.55.0 class doesn't know about it. The original provider can always re-announce with samples intact. Acceptable — gossip republish has been deprecated since v0.51.1, KAD is primary.

- **TaskRequest URI validation is permissive.** Empty `uri` field bypasses validation and routes via flat `skill_name`, for backward compat with v0.55.0 clients. Migration horizon (Phase 2 warn, Phase 3 require) filed for future sprints.

- **Thread pool split is complete but not enforced.** v0.56.0 migrates the last known protocol-critical sync operations explicitly to `_run_in_protocol_pool`. Future contributors can still accidentally use `asyncio.to_thread(...)` which routes to the handler pool via `set_default_executor`. Filed for v0.57.0 (`CR-explicit-pool-wrappers`) — adds `to_protocol_thread` / `to_handler_thread` wrappers + grep hygiene test.

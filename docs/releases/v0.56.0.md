# v0.56.0 — Transport Identity Binding

**Release date:** 2026-04-11 (superseded by v0.56.1 — see `v0.56.1.md` for the shipping tag)
**Baseline:** v0.55.0 "Security Foundation"
**Scope:** 11 Tier 1 items + 1 scope amendment, ~700 LOC source + ~300 LOC tests

## Summary

v0.56.0 binds transport-layer identity to `node_id`s and closes a default-grant ACL. TOFU cert pinning ties peer TLS fingerprints to `node_id`s on first contact. Default-deny replaces implicit `all_signed` access on punchhole cache objects. Commerce chain URIs gain first-class addressability across seven schema tables. Two exp-201 blockers ship (`query_plugin` hoist, heartbeat epoch bridge) alongside five debt items pulled from "defer and forget."

One amendment landed late: an optional `samples` field on `SkillSheet` carrying Ed25519-signed quality evidence for downstream discovery clients.

---

## ⚠ BREAKING — Default-deny ACL on punchhole frontend (C-02)

**Impact:** Nodes serving punchhole cache objects to unknown requesters will now reject them instead of implicitly granting baseline access.

### What changed

Previously, when a requester's `node_id` was not in the backend's ACL map, the frontend defaulted the tier to `"all_signed"` and served the cache object to any signed peer. Any signed requester on the network got baseline access without the operator opting in — a default-grant security posture.

v0.56.0 changes the default to **deny**. Unknown requesters are rejected with:

```
PUNCHHOLE_ACL_DENY node_id=<id> reason=unknown_and_no_public_signed_tier
```

Grep logs for this line to identify rejected peers and decide whether to grant access explicitly.

### How to restore access for a specific peer

The ACL map in v0.56.0 is assembled from three runtime sources:

1. **`peer`** — nodes that have either announced a skill (skill announce) or established a bilateral ledger relationship
2. **`known_hosts`** — nodes in the local address book with `tier = 'explicit'`
3. **`trusted`** — nodes listed in `trusted_nodes = [...]` in the exposure schema

To grant baseline access to a specific peer, add their 64-char hex `node_id` to `trusted_nodes`:

```toml
# exposure_schema.toml
trusted_nodes = [
    "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
]
```

After backend reload, listed peers are pushed to the frontend ACL map with tier `trusted`. Objects with `access = "trusted"` then serve them. Alternatively, establish a bilateral ledger relationship (promotes them to `peer` tier) or add them to `known_hosts` with `tier = 'explicit'`.

**Note:** the sprint brief originally referenced a `public_signed` ACL tier as the operator escape hatch. v0.56.0 uses the existing `trusted_nodes` mechanism instead — functionally equivalent, no new config schema needed.

### Why hard cutover, no config knob

The team network has no external peers today, but adversarial exposure is imminent. A permissive default with a backward-compat opt-out knob is a footgun operators won't flip until after an incident. v0.56.0 ships default-deny without an escape hatch so the ACL map becomes the explicit, auditable source of truth.

## Shipped items

### Transport identity binding

**C-01 — Minimal TOFU cert pinning + hybrid AAD binding + recovery CLI** (~100 LOC)

Trust-on-first-use TLS fingerprint pinning. On first signature-verified contact, a peer's cert fingerprint is stored keyed by `node_id`. Subsequent mismatches trigger a `security.cert_pinning_mismatch` bus event and reject the connection with `CertPinMismatchError`. Bidirectional: server (`_handle_connection`) and client (`request_response`, pool `_try_send`) extract the fingerprint at handshake and attach it to the verified message.

Additionally: `core/crypto.hybrid_encrypt` / `hybrid_decrypt` bind the canonicalized sorted recipient list into AES-GCM AAD, preventing reorder/tamper attacks on the wrapped key set. New CLI: `knarr peer forget-fingerprint <node_id>` clears stored fingerprints after a legitimate cert rotation.

**Honest framing:** TOFU does NOT protect against a MITM already in position at first contact. The claim is "cert fingerprint pinned on first contact, mismatch on subsequent contacts is rejected" — NOT "cert identity cryptographically verified." First-contact MITM requires DHT compromise, a separate attack class addressed by Ed25519 announcement signatures. Full PKI (rotation, revocation, chain validation beyond `CERT_NONE`) is deferred to a dedicated TLS hardening sprint.

Files: `dht/node.py`, `dht/pool.py`, `dht/protocol.py`, `dht/storage.py`, `core/crypto.py`, `cli/main.py`

**C-02 — P-01 auth gate default-deny ACL** (~30 LOC)

See the breaking change section above. `plugins/08-punchhole-frontend/handler.py` default fallback changes from `"all_signed"` to `""` (deny) when an unknown `node_id` requests a cached object.

Files: `plugins/08-punchhole-frontend/handler.py`

### Commerce chain URI addressability

**T2-01 — Additive URI field on TaskRequest** (~40 LOC)

`TaskRequest` gains an optional `uri: str = ""` field. v0.56.0+ providers populate it with `knarr://{provider}/s/{skill}@{version}`. Receiver-side validation uses `parse_knarr_uri` + skill-match policy check — rejects cross-field mismatches with `security.uri_mismatch` bus events naming the specific failure (`invalid_uri`, `bad_selector`, `skill_mismatch`, `authority_mismatch`).

v0.55.0 clients continue working: empty URI bypasses validation and routes via the flat `skill_name` field. Migration horizon (Phase 2 warn, Phase 3 require) tracked for v0.57.0+ in `CR-taskrequest-uri-migration-horizon.md`.

Files: `core/messages.py`, `dht/node.py`

**T2-02 — URI column expansion across commerce schema** (~80 LOC)

Seven tables gain `uri TEXT NOT NULL DEFAULT ''` + index: `skills`, `tasks`, `execution_log`, `async_jobs`, `mail_inbox`, `mail_outbox`, `settlement_queue`. Existing rows populated via migration `UPDATE` templates derived from existing columns. Storage helpers updated to populate URIs on new inserts.

Files: `migrations/v0_56_0.sql`, `dht/storage.py`, `commerce/netting.py`

### Developer-facing infrastructure

**T1-01 — `query_plugin` hoist to DHTNode + `current_identity_name` helper** (~100 LOC)

`query_plugin` hoisted from `PluginContext` to `DHTNode` so skill handlers can call `NODE.query_plugin(...)` directly, not just plugins. `PluginContext.query_plugin` is a thin delegation shim — existing plugin callers unchanged. `PluginContext.current_identity_name()` returns the scoped identity name (or `None` in router context) without importing core contextvar internals.

Files: `dht/node.py`, `dht/plugins.py`

**T1-02 — PREREQ-01 heartbeat epoch bridge** (~80 LOC)

The `punchhole_epoch` field on the Heartbeat dataclass (shipped empty-default in v0.55.0) is now populated from the live backend counter at all 4 construction sites. Remote nodes receive epoch increments and can trigger targeted re-crawls of specific peers instead of periodic full crawls.

Files: `dht/node.py`, `plugins/09-punchhole-backend/handler.py`

### Resource isolation

**T2-09 — Thread pool split migration + audit report** (~15 LOC + audit)

Remaining protocol-critical sync operations in `_reannounce_all`, `_evict_bootstrap_peers`, and several mail sync paths migrated from the handler pool (default executor) to the explicit `_run_in_protocol_pool` helper. Audit report at `thing/sprints/tests-v0.56.0/item-4-thread-pool-audit.md` documents migrated sites, sites that stayed, the `set_default_executor` decision rationale, and before/after p99 heartbeat timing measurements under stress.

Files: `dht/node.py`, `mail/sync.py`

### Node setup ergonomics

**T2-08 — Plugin loader package-path fallback** (~35 LOC)

Plugin loader falls back to `importlib.resources.files("knarr.plugins")` when the node-local `plugins/` directory lacks a plugin. Built-in plugins at `src/knarr/plugins/*` are auto-discoverable on fresh node setup without manual symlinking. Plugins with missing required config are skipped with a WARNING and other plugins continue loading.

Files: `dht/plugins.py`

**T2-08b — `knarr init --profile` mechanism + minimal template** (~30 LOC)

`knarr init` gains a `--profile <name>` flag. Template loader reads `src/knarr/templates/profiles/<name>/`. One template ships: `minimal` — unopinionated bootstrap node with no thrall, recipes, or persona. Uses `string.Template.safe_substitute` to apply `--port` and `--bootstrap` arguments. Refuses to overwrite existing directories. Opinionated profiles (developer, elder, experiment) defer to the repo that owns the opinion.

Files: `cli/main.py`, `templates/profiles/minimal/*`

### Operator experience

**T3-03 — TLS config section mismatch warning** (~10 LOC)

`cli/config.py` warns on unknown top-level TOML sections at load time via the standard logging pipeline (`knarr.cli.config` logger at WARNING). Names the offending section (`CONFIG_UNKNOWN_SECTION section=[transport] ...`) and lists known sections. Closes the silent-config-ignore trap hit during v0.55.0 cluster testing.

Files: `cli/config.py`

**T3-06 — Sidecar quota drift from encryption overhead** (~10 LOC)

Sidecar asset quota accounting now tracks actual disk usage including encryption overhead. Uses `len(disk_data)` (post-encryption bytes) for metadata and `_total_size`. New constant `KNARR_ASSET_ENCRYPTION_OVERHEAD = 40` documents PyNaCl SecretBox overhead for the pre-write quota check.

Files: `dht/sidecar.py`

### Scope amendment — SkillSheet `samples` field (~160 LOC)

Landed late in assembly to support the Argus-style quality-rating workflow in exp-201. `SkillSheet` gains an optional `samples` field carrying Ed25519-signed quality evidence records. Schema validation in `core/validation.py` enforces shape (required sub-fields, verdict whitelist, hex regex on rater keys, per-entry + total size caps) without verifying the cryptographic signatures. Consumer-side `verify_skill_sample(sample, rater_pubkey=None)` in `core/crypto.py` performs the Ed25519 signature check plus `rater_node_id == sha256(rater_pubkey)` consistency. Consumer trust list is a client-side concern, filed as `CR-rater-trust-list` for v0.57.0.

Size handling: `MAX_SAMPLES_SIZE = 32768` (32 KB total), `MAX_SAMPLES_ENTRIES = 10`, `MAX_SAMPLE_ENTRY_SIZE = 3200`. Samples excluded from the 4 KB base skill-sheet cap, mirroring the existing `input_schema_full` exclusion.

Files: `core/models.py`, `core/validation.py`, `core/crypto.py`

## Known limitations

- **Cert pinning is TOFU, not PKI.** A MITM in position at first contact with a new peer will pin their own fingerprint as legitimate. Use `knarr peer forget-fingerprint <node_id>` after any legitimate cert rotation. Full PKI extension filed as `SPEC-tls-cert-pinning-pki.md`.

- **Samples field has no consumer trust list yet.** v0.56.0 ships the `samples` field and `verify_skill_sample()` helper but defers client-side rater trust list config to v0.57.0 (`CR-rater-trust-list`). Consumers who want to act on rating evidence must maintain their own `rater_node_id → rater_pubkey` mapping until the operator-facing config lands.

- **v0.55.0 nodes drop samples on re-emission.** When a v0.55.0 node receives an Announce with `samples` and later re-announces (gossip republish, KAD provider republish), the `SkillSheet.from_dict → to_dict` path drops the field because the v0.55.0 class doesn't know about it. The original provider can always re-announce with samples intact. Acceptable — gossip republish has been deprecated since v0.51.1, KAD is primary.

- **TaskRequest URI validation is permissive.** Empty `uri` field bypasses validation and routes via flat `skill_name`, for backward compat with v0.55.0 clients. Migration horizon (Phase 2 warn, Phase 3 require) filed for future sprints.

- **Thread pool split is complete but not enforced.** v0.56.0 migrates the last known protocol-critical sync operations explicitly to `_run_in_protocol_pool`. Contributors can still accidentally use `asyncio.to_thread(...)`, which routes to the handler pool via `set_default_executor`. Filed for v0.57.0 (`CR-explicit-pool-wrappers`) — adds `to_protocol_thread` / `to_handler_thread` wrappers + grep hygiene test.

## Post-release note

v0.56.0 was built, merged to a feature branch, and cluster-tested — but never tagged. G-18 caught a `TaskRequest` URI validator regression on the first cross-machine run: `_identity_registry.resolve()` returned `None` on single-identity nodes, rejecting every cross-node `TaskRequest` with `URI_MISMATCH`. The fix shipped as **v0.56.1** on 2026-04-11. Public history jumps from v0.55.0 → v0.56.1 with no broken tag in between. See `v0.56.1.md` for the shipping tag notes and the self-target fast-path fix detail.

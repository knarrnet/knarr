# Release Notes — v0.55.0 "Security Foundation"

**Date:** 2026-04-08
**Base:** v0.54.1

---

## Summary

All cryptographic operations consolidated into `core/crypto.py`. TLS added to the main TCP protocol. Content encryption extended to system mail and sidecar assets. Punchhole remote authentication fixed. Hybrid multi-recipient encryption primitives added. Six small fixes across settlement, storage, dashboard, mail, and status API.

## Crypto Consolidation (C-01)

- **New module** `core/crypto.py` — single import path for all NaCl operations.
- Re-exports NaCl types (SigningKey, VerifyKey, SealedBox, SecretBox) plus high-level traced wrappers.
- 17 consumer files refactored from direct `nacl` imports to `core.crypto`.
- `grep -r "from nacl" src/knarr/` returns only `core/crypto.py` (plus frozen `cli/main.py`).

## TLS on TCP (C-02)

- Main TCP server and connection pool now use TLS by default.
- Config: `[node] tls = true`, `tls_required = true`, `tls_cert`, `tls_key`.
- Auto-generates self-signed cert if none configured.
- `tls_required = true` aborts startup if certs unavailable (fail-closed).
- `tls_required = false` falls back to plaintext with WARNING for mixed-version networks.

## System Mail Encryption (C-03)

- All mail types (including `knarr/commerce/*` system mail) now encrypted when peer X25519 key available.
- Encryption failure skips the item (fail-closed) instead of sending plaintext.

## Sidecar Asset Encryption at Rest (C-04)

- Assets encrypted with vault SecretBox before writing to disk.
- Hash computed from plaintext (preserves dedup). Ciphertext stored on disk.
- Encryption failure rejects upload with 500 (fail-closed).
- Backward-compatible: unencrypted pre-v0.55.0 assets served on decrypt failure.

## Hybrid Encryption Helpers (C-05)

- `hybrid_encrypt(plaintext, recipient_pubkeys)` — AES-256-GCM content + per-recipient X25519 key wrapping.
- `hybrid_decrypt(payload, private_key)` — O(1) recipient lookup by public key hex.
- Plugin primitives — no core consumer. Empty recipient list raises ValueError.

## Punchhole Auth Fix (P-01) — CRITICAL

- **Root cause:** `_hex_to_verify_key()` passed node_id (SHA-256 hash) to VerifyKey. All remote punchhole queries failed.
- **Fix:** Look up actual Ed25519 public key via `storage.get_pubkey_by_node_id()`.
- Inner payload re-verification skipped when pubkey unavailable (outer PluginMessage already verified).

## Punchhole Card Query (P-02)

- `action="CARD"` handler in punchhole frontend.
- Returns `build_card(requester_node_id)` via public `ctx.get_plugin()` API.
- Addressable as `knarr://node_id/p/card`.

## Small Fixes

- **S-01:** Settlement receiver-side dedup via `has_pending_settlement()`.
- **S-02:** WAL checkpoint (`PRAGMA wal_checkpoint(RESTART)`) on storage close.
- **S-04:** Explicit provider matching own node_id routes through local fast path. Result now stored in job status.
- **S-05:** `session_id` and `reply_to` read from both top-level request and nested body.
- **S-06:** `public_key` field added to `/api/status` response.

## Adversary Findings Fixed

- C-04/C-03 fail-open on encryption error → fail-closed (6/7 adversaries)
- C-02 tls_required=true silent plaintext degradation → RuntimeError (5/7)
- S-01 balance==0.0 dedup → reverted to has_pending_settlement (5/7)
- S-04 local task output discarded → result passed to job status (1/7, Gemini)
- C-05 empty recipient list accepted → ValueError (2/7)

## Files Changed

21 source files, 4 new test files. `core/crypto.py` is the only new source file.

## Testing

- 67 sprint tests, 79 regression tests, 16 Wave 1 tests — all pass.
- Full suite (290 files, batched): zero regressions.

# Knarr v0.36.0 — Handsal Settlement

**Release date:** 2026-03-04
**Status:** Cluster gate pending

## Summary

Handsal ("handshake") introduces the dual-signature settlement protocol. Bilateral debts
are now settled through a two-party cryptographic handshake: the proposer signs with their
node key (`#key-1`), and an independent authority countersigns (`#cockpit-1` or `#thrall-1`).
This prevents unilateral ledger manipulation.

## New Features

### Dual-Signature Settlement (B3)
- `settlement_prepared` → `settlement_accepted` → `settlement_processed` → `settlement_confirmation`
- Node key signs the proposal, cockpit/authority key countersigns
- Fail-closed: missing or unverifiable authority signature = rejection
- Amount-based ledger adjustment (settles the agreed amount, not full zero)

### Settlement Engine (P-010)
- Pure-function settlement evaluation: `SettlementInput` → `SettlementOutput`
- Spec formula: `amount = balance - (soft_target * hard_limit)`
- Configurable min_settlement_amount, soft_target, cadence

### Prepaid Engine (P-010)
- Pure-function prepaid evaluation: `PrepaidRequest` → `PrepaidResult`
- Deduct / skip / reject decisions based on balance and task price
- NaN/Inf rejection on all numeric inputs

### Local Skill Fast Path (A1)
- Same-node skill calls skip the async queue
- Identical receipts to the async path (P-003 compliance)
- Per-skill active count tracking with `SKILL_BUSY` rejection

### Netting Cycle (B1)
- Automatic settlement initiation when utilization exceeds soft threshold
- `has_pending_settlement` guard prevents duplicate proposals
- Settlement queue with priority ordering

### Cockpit Settlement UI (B6)
- Manual settlement initiation via `POST /api/settle/{peer}`
- Cockpit countersigns with authority key, appending `authority_proof`

### Commerce Document Registry
- Typed document factories for all settlement lifecycle stages
- RFC 8785 canonical JSON for deterministic signing
- Document verification via `verify_document(doc, verify_key)`

### Plugin Hooks
- `on_inbound_settlement(body)` — plugin gate for settlement acceptance
- `sign_document` and `query_receipts` exposed in PluginContext

## Security Fixes (Adversary Panel)

5-model adversary panel identified 38 findings. All CRITICAL through MEDIUM fixed:

- **C2:** Authority key fail-closed on unresolvable verification method
- **C3:** Require signed document with proof in settle_request
- **C4:** Amount-based ledger adjustment (not unconditional zero)
- **H2:** Eliminated `peer_key` fallback (prevented third-party ledger zeroing)
- **H4:** Fail-closed plugin default (reject when plugin raises)
- **H5:** Settle-request replay dedup via receipt_log
- **H6:** Settlement confirmation replay dedup
- **H8:** Reconciliation divergence uses own position (not attacker's claim)
- **M1:** NaN/Inf rejection on all settlement amounts
- **M2:** Cockpit countersign appends authority_proof (not overwrite)
- **M4:** `has_pending_settlement` uses full 64-char key (no truncation)
- **M6:** `_skill_active` decrement inside finally block (cancellation safe)
- **M8:** Zero-balance settlement requests rejected
- **M9:** Envelope sender must match document proposer

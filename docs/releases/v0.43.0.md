# Release Notes — v0.43.0 "Hardening"

**Date:** 2026-03-12
**Branch:** `feature/v0.43.0`
**Base:** v0.42.0

---

## Summary

Hardening sprint focused on settlement pipeline correctness, core wiring, and node.py structural cleanup. Fixes the dual-signature settlement failures introduced in v0.42.0 (A1/A2/A3), adds operator-configurable routing and punchhole private ACL tier, and extracts mail handlers and secrets manager into standalone modules. Four-model dev panel (Gemini, GPT-5.4, Sonnet, Qwen), three-judge panel (GPT-5.4, Gemini, Opus).

## Breaking Changes

None.

## Track A — Settlement Pipeline Fixes

### A1: Settlement Verify Key Resolution

`_handle_settlement_request()` now resolves the proposer's verify key from the proof's `verificationMethod` DID fragment via `resolve_did_fragment()`. Falls back to `peer_key` from the mail body only if DID resolution fails. Eliminates the hardcoded key path that blocked settlement execution in v0.42.0.

### A2: Settlement Countersign Fragment Fix

When the node countersigns a document, it now uses `#key-1` as the DID fragment identifier. Previously used `#cockpit-1`, which caused verification failures against the node's primary key.

### A3: DID Fragment Key Class Resolution

New `resolve_did_fragment(did)` method on `DHTNode`. Parses the DID and fragment, returns the correct `VerifyKey` for the local node's known fragments (`#key-1`, `#cockpit-1`, `#thrall-1`). Returns `None` for unknown fragments or remote peers (no fallback to a wrong-class key).

### A4: Config Parser False-Positive Warnings

`_warn_unknown_keys()` in `cli/config.py` no longer warns on dict-typed sub-keys (e.g., `[skills.my-skill]`, `[economy.settlement]`). TOML sub-tables and `[peer_overrides]` sections are skipped cleanly.

### A5: Cockpit `/api/execute` String Provider

When a skill provider is specified as a plain string node ID instead of a dict, the cockpit execute handler now normalizes it to `{"node_id": provider}` before processing instead of crashing on `.get()`.

## Track B — Core Wiring

### B1: `send_mail` in Skill Handler Context

Skill handlers now receive a `_send_mail` callable in their `input_data` dict. Allows handler code to send system mail without direct node access. Implemented as a bound partial of `DHTNode.send_mail()` injected at dispatch time.

### B2: Routing Policy via `routing.toml`

Operator-configurable execution routing. When `routing.toml` is present in the node data directory, `local_weight` (0.0–1.0) controls how the cockpit scores local vs remote execution candidates. Weight loaded at startup, cached, reloaded on SIGHUP. Default: 1.0 (always prefer local).

### B3: Punchhole Private ACL Tier

New `"private"` ACL tier in the punchhole exposure schema. Four private objects built at startup and accessible only via `get_private_object()` (local node use):
- `economy.full` — per-peer bilateral ledger positions and credit balances
- `positions.full` — net positions with utilization ratios
- `peers.status` — connected peers with IP addresses and last-seen timestamps
- `skills.inventory` — full skill catalog with pricing and configuration

External requesters cannot request or receive private-tier objects.

## Track C — Node.py Carve-Outs

### C1: Mail Handlers → `dht/mail_handlers.py`

Four mail handler methods extracted from `DHTNode` into a new `MailHandlers` class in `dht/mail_handlers.py` (~328 LOC). Late-bound dependencies wired via `bind_runtime()` pattern. Handlers registered directly with the sync engine; node retains delegation stubs for backward compatibility.

### C2: Secrets Manager → `dht/secrets.py`

Secrets injection logic (master key derivation, cert generation, vault setup) extracted from `DHTNode.__init__()` into a new `SecretsManager` class in `dht/secrets.py` (~106 LOC). `load()` uses in-place dict mutation (`clear()` + `update()`) to avoid stale reference bugs.

## Known Issues

| Severity | Component | Description |
|----------|-----------|-------------|
| Medium | settlement | `resolve_did_fragment` returns `None` for remote peers — fragment-aware sub-key resolution for remote nodes requires DID document lookup (v0.44.0+) |
| Low | routing | `local_weight` acts as a binary threshold (below 1.0 = always remote, at 1.0 = always local) — probabilistic weighted selection deferred to v0.44.0 |
| Low | punchhole | `economy.full` private object payload shape requires `{"economy": ...}` wrapper to match `exposure_schema.toml` field declaration |

# v0.58.0 — Security & Foundations

**Release date:** 2026-04-27
**Baseline:** v0.57.0 "Structural Debt Retirement"
**Sprint goal:** Security hardening across the signing, settlement, plugin, and BCW layers. No new user-facing features — attack surface reduction, robustness, and one new operator capability (dynamic skill registration).
**Scope:** 10 items, ~500 LOC shipped + ~200 LOC tests

---

## Summary

v0.58.0 tightens five security boundaries that emerged from the competitive adversary panel (6 models, 6 rescue dirs):

- **Signing integrity** (C-05): `.knarr` archives now carry a detached Ed25519 signature; install can enforce a signer policy at the operator level
- **Dynamic skills** (C-01): new dashboard endpoint with three independent guards — enable flag, count cap, signed-package policy — preventing bypass via the cockpit API
- **Settlement serialization** (A-06): blocking storage ops moved off the async loop; duplicate-receipt guard added before write
- **BCW mint filter** (A-09): only the configured KNARR mint address routes to `payment_received`; `None`/empty bypass closed
- **Sample freshness** (A-01): future-timestamp bypass in `verify_skill_sample` closed; `trusted_raters` now wired from operator config

Five bugs found and fixed by the adversary panel (C-05-ADV-01, C-01-ADV-02/03/04, A-01-ADV-01). Two panel findings ruled false positives.

## Shipped items

### A-01 — Sample verification hardening

`verify_skill_sample` in `core/crypto.py` had two gaps:

1. **Future timestamp bypass:** `current_time - timestamp_seconds` is negative when `timestamp_seconds > current_time` — always less than any positive `max_age`. Samples with future timestamps were permanently "fresh". Fix: `if timestamp_seconds > now + 300: return False` added before the age check (300 s clock-skew tolerance).

2. **`trusted_raters` never wired:** The `trusted_raters` parameter was accepted but never passed from any call site — any node could inject samples. Fix: call sites in `node.py` now read `config.reputation.trusted_raters` and pass it through.

**Files:** `src/knarr/core/crypto.py`, `src/knarr/dht/node.py`

---

### A-02 — Plugin root path validation

Plugin loader validates that the resolved handler path is within the configured plugin root before loading. Prevents handler path escapes via relative traversal in `skill.toml`.

**Files:** `src/knarr/cli/config.py`, `src/knarr/dht/plugins.py`

---

### A-05 — TLS pin-certs startup lock

Peer TLS cert snapshots taken once at node startup into an immutable dict. Runtime config re-reads can no longer silently change which cert a peer is pinned to mid-session. `F9` fix included: cert serial is now `SHA-256(node_id[:20])` — deterministic across restarts, ending `CERT_PIN_MISMATCH` on cert rotation.

**Files:** `src/knarr/mail/tls.py`

---

### A-06 — Settlement write serialization

`execute_settlement` in `settlement_execution.py` had two issues:

1. **Sync SQLite on async loop:** `_storage_read` called storage ops directly on the event loop thread. All calls now wrapped in `run_in_executor`.
2. **No duplicate-receipt guard:** concurrent submissions could double-execute. Dedup check added before the write.

**Files:** `src/knarr/commerce/settlement_execution.py`

---

### A-09 — BCW mint guard ingestion

`handler.py` guard changed from `if transfer.mint_address and transfer.mint_address != self._knarr_mint()` to `if transfer.mint_address != self._knarr_mint()`. The original short-circuit `and` let `mint_address=None` (native SOL) and `mint_address=""` through the KNARR payment path. Native SOL transfers now reach the native SOL handler only.

**Files:** `src/knarr/plugins/10-bcw/handler.py`

---

### B-01 — SQL migrations parser robustness

Two fixes to `_split_statements` in `core/migrations.py`:

1. **Escaped-quote off-by-one:** `''` (SQL literal quote) consumed the second quote then `continue`-d — jumping to the outer loop's `i += 1`, dropping the character after `''`. Fixed with `i += 1; continue` in the escaped-quote branch.
2. **Partial migration silently re-skipped:** migration marked `applied` even when individual statements raised real errors. Now only marked applied when all statements succeed; idempotent errors (table-already-exists etc.) are distinguished from real failures.

**Files:** `src/knarr/core/migrations.py`

---

### B-03 — Punchhole `failed_count` persistence

`v0_58_0.sql` adds `failed_count INTEGER DEFAULT 0` to `punchhole_peers` and creates `skill_registry` for dynamic skills. Punchhole backend increments `failed_count` on failure, resets to 0 on success. Exposes per-peer failure history to operators via the storage layer.

**Files:** `src/knarr/migrations/v0_58_0.sql`, `src/knarr/plugins/09-punchhole-backend/handler.py`

---

### B-06 — Plugin drift detection

`dht/plugins.py` drift detection now constructs `local_config` correctly — the previous path included an extra `.name` component that caused the drift check to never match. Operators relying on drift detection to catch out-of-band plugin config changes will now see alerts fire correctly.

**Files:** `src/knarr/dht/plugins.py`

---

### C-01 — Dynamic skills endpoint

New cockpit endpoint `POST /api/skill/register` — accepts a Python source body, validates syntax, writes to `dynamic_skills/{name}.py`, registers as a node handler. Three independent guards:

- `dynamic_enabled` policy flag — defaults to `false`; endpoint 400s when false
- `max_dynamic_skills` cap — computed from actual `load_dynamic_skills()` count, not a hardcoded zero
- `require_signed_packages` policy — unsigned installs refused via dashboard API as well as CLI path

`cmd_skill_remove` path confinement: handler path verified inside `config_dir` via `Path.resolve().is_relative_to(config_root)` before `os.remove()`. Body size capped at 65 536 bytes.

**Files:** `src/knarr/dashboard/server.py`, `src/knarr/cli/config.py`

---

### C-05 — `.knarr` archive signing

`knarr skill pack --sign` produces a detached `.sig` alongside the archive. The signature document (`document_type: knarr_archive_signature`) contains the archive SHA-256, the signer's public key, and an Ed25519 proof via `sign_document` (eddsa-jcs-2022). The archive itself is byte-identical whether signed or not.

`knarr skill install --verify-signer <node_id|"any">` validates the detached `.sig`: checks `document_type`, verifies `archive_sha256`, verifies the Ed25519 proof, and matches the signer identity. Missing sig → refuse. Hash mismatch → refuse. Signer mismatch → refuse. `"any"` accepts any valid signer. `require_signed_packages=true` in policy enforces verification on every install path including the dashboard API.

**Files:** `src/knarr/cli/skill.py`, `src/knarr/core/proof.py`

# Knarr v0.34.0 — Receipt Foundation

**Date:** 2026-03-02

## Summary

Append-only receipt logging for all economic and mail operations. Every skill execution, credit note, mail delivery, and mail receive now generates a signed, timestamped receipt in a new `receipt_log` table. Receipts use W3C Data Integrity proof format with Ed25519-JCS cryptosuite.

## Changes

### Receipt Infrastructure
- New `_write_receipt()` centralized helper on DHTNode
- `receipt_log` table: append-only, indexed by document_type, counterparty, order_ref
- Receipt ID format: `{type_prefix}_{token_hex(8)}` (e.g. `exec_a1b2c3d4e5f6a7b8`)
- Timestamp format: ISO 8601 with millisecond precision (`2026-03-02T14:30:00.123Z`)
- Canonical JSON serialization with `sort_keys=True, separators=(',',':')` for deterministic hashing
- Signed receipts include `ed25519:` prefixed hex signature

### Receipt Types
- `execution_receipt` — skill execution (success and failure)
- `credit_note` — credit/debit settlement
- `mail_delivery_receipt` — mail delivery acknowledgment/failure
- `mail_receive_receipt` — mail receive confirmation/duplicate detection
- `order_ack` — task acceptance acknowledgment
- `order_executing` — task execution start

### Commerce Hardening
- Refund sender verification: reject refund requests from non-requesters
- Signed credit note validation with field-level checks
- Amount validation: reject non-positive and > 2x original price

### HTTP Port Confusion Fix (A1)
- Protocol port now peeks first 4 bytes and rejects HTTP requests
- Case-insensitive verb detection
- Emits `security.http_rejected` bus event

### Adversary Hardening (18 fixes from 4-model attack panel)

**HIGH/MEDIUM (10):**
- Payload dict shallow-copied before mutation (no caller side effects)
- `signer_id` initialized before message loop (prevents NameError)
- Cryptosuite field only set when signing key available
- Sync path receipt writes migrated to `_write_receipt()` (format consistency)
- `allow_nan=False` on receipt JSON serialization (RFC 8259 compliance)
- Body hash uses `json.dumps()` for all types including lists
- Duplicate receive receipts include `payload_hash: None` for schema consistency
- Warning logged when `_write_receipt` method unavailable (no silent skip)
- Refund sender verification on commerce handlers
- Signed credit note field-level validation

**LOW (8):**
- HTTP peek timeout reduced from 5s to 2s
- Malformed public key rejection at message entry (odd-length hex, non-hex chars)
- Non-serializable mail body fallback to `str()` on 3 receipt hash sites
- `wall_ms` clamped to `[0, 86400000]` at all 4 `timedelta` sites
- Bus event `receipt.write_failed` emitted on storage exception
- Receipt ID entropy increased from 48-bit to 64-bit (`token_hex(8)`)
- Queue-full rejection now writes `order_ack` receipts on both admission paths
- Graceful connection close when reader lacks `_buffer` (HTTP peek fallback)

# Release Notes — v0.41.0 "Tighten the Membrane" (Mail Pricing + Identity Persistence, Adversary-Hardened)

**Date:** 2026-03-09
**Branch:** `feature/v0.41.0`
**Base:** v0.40.1

---

## Summary

Tighten the Membrane wires the economic admission pipeline into inbound mail, adds `--data-dir` for identity/wallet persistence across upgrades, fixes tick starvation by extracting network I/O into independent background loops, and ensures free skills stay free. Five-model adversary panel (Opus, GPT-5.4, Sonnet, Gemini, Qwen — 47 exploit tests) identified 17 deduplicated findings. 6 fixed, 5 deferred to v0.42.0, 6 dismissed as false positives.

## Breaking Changes

None. All changes are backward-compatible. Nodes without `--data-dir` continue to use `dirname(knarr.toml)` for all state.

## New: Identity Persistence + `--data-dir` (A1)

New CLI flag decouples persistent state from install path, solving Docker image upgrades wiping identity and wallet keys.

```bash
knarr serve --data-dir /data/knarr
```

**Priority chain:** `--data-dir` CLI flag > `KNARR_DATA_DIR` env var > `[node] data_dir` config > `dirname(config_path)`

**What moves to data_dir:**
- Identity: key.pem, cert.pem, cockpit certs
- Wallets: secrets.toml, plugin wallet keys
- State: node.db, vault.db, .cockpit_token, knarr.pid
- Plugin state: `data_dir/plugin_state/<plugin_name>/` (DBs, keys)

**What stays in config_dir:** knarr.toml (and tier files)

**Plugin changes:**
- `PluginContext` gains `state_dir` field
- When `data_dir` is set: `state_dir = data_dir/plugin_state/<name>/`
- When `data_dir` is not set: `state_dir = plugin_dir` (backward compatible)
- BCW and Punchhole plugins updated to use `ctx.state_dir`

**First-boot behavior:**
- Empty data_dir: generates identity, creates directory structure, emits backup instruction to stdout
- Populated data_dir: uses existing files
- No auto-migration: if identity files exist in both locations, a warning is logged

**Upgrade changes:**
- `backup_config()` and `rollback_installation()` accept optional `data_dir` parameter
- Config file (knarr.toml) always sourced from config_dir; data files from data_dir

## Fix: Tick Starvation — Background-Task Extraction (A2)

Three network I/O operations extracted from `_heartbeat_tick()` into independent `asyncio.create_task()` loops:

| Loop | Config Key | Default | Timeout |
|------|-----------|---------|---------|
| `_flush_outbox_loop` | `[node] flush_interval` | 10s | 5s |
| `_pull_from_correspondents_loop` | `[mail] pull_interval` | 300s | 5s |
| `_peer_heartbeat_sweep_loop` | `[node] sweep_interval` | 10s | 10s |

`_heartbeat_tick()` now contains only: cleanup, plugin tick, bus tick, pool eviction, netting. Plugin `on_tick()` is no longer blocked by slow network I/O.

Intervals clamped to minimum 1.0s to prevent CPU spin on misconfiguration.

Shutdown awaits all background tasks via `asyncio.gather()` before closing storage.

## New: Mail-as-Skill Pricing (B1)

Inbound mail now goes through the admission pipeline. This is the economic membrane for mail — senders are charged per-message using the same pricing infrastructure as skill calls.

**Admission flow (both push and pull paths):**
1. System mail (`msg_type` starting with `knarr/`) bypasses admission entirely
2. Non-system mail: validate sender key, run admission pipeline
3. Accepted: store mail, debit sender via `update_ledger_provider`
4. Rejected (hard_block): emit `credit.sanctioned` event, ACK item to sender (terminal — no retry)

**Configuration:**
```toml
[mail]
price = 1.0  # base price per inbound mail
```

Felag members receive discounts via existing tier pricing rules. Initial credit and minimum balance from `[policy]` apply.

## Fix: Pricing Parity (B2)

Free skills (`base_price == 0.0`) now return `final_price = 0.0` immediately in `_resolve_price_builtin()`, bypassing all discount, floor, surcharge, and cap logic. Previously, a free skill could be rounded up to the global minimum price.

### Fixed

| # | Finding | Consensus Severity | Fix |
|---|---------|-------------------|-----|
| F1 | Pull path admission bypass (empty public_key) | HIGH | Reject mail when `resp.public_key` is empty instead of skipping admission |
| F2 | System mail spoofing via msg_type handler lookup | HIGH | `msg_type.startswith("knarr/")` prefix check replaces handler lookup |
| F3 | `bytes.fromhex` crash on invalid hex sender key | MEDIUM | try/except ValueError, reject malformed item, continue batch |
| F4 | Zero/negative background loop intervals | MEDIUM | `max(1.0, float(...))` on all three loops |
| F6 | Hard-blocked mail retries forever (no terminal ACK) | HIGH | Rejected item IDs added to `confirmed_ids` so sender gets ACK |
| F7 | Negative mail price credits sender | MEDIUM | `max(0.0, result.pricing.final_price)` before ledger update |

### Deferred to v0.42.0

| # | Finding | Severity | Reason |
|---|---------|----------|--------|
| F5 | Backup misses plugin_state/vault.db | MEDIUM | Pre-existing limitation amplified by A1, not a membrane hole |
| F8 | `knarr upgrade` missing `--data-dir` flag | MEDIUM | Upgrade path is separate concern, CLI-only deployments rare |
| F9 | Relative TLS paths rebase to data_dir | MEDIUM | Edge case affecting custom cert + explicit data_dir |
| F10 | SIGHUP split-brain (storage pinned to old paths) | LOW | Requires restart for data_dir change; log warning sufficient |
| F11 | Re-bootstrap storm (no backoff) | LOW | Pre-existing pattern, not a regression |

### False Positives Dismissed

| Finding | Source | Reason |
|---------|--------|--------|
| Path traversal in _resolve_data_dir | Adv5 | Operator-controlled input (CLI/env), not attacker-reachable |
| Symlink attack in plugin state | Adv5 | Requires filesystem write access — game already over |
| update_ledger_provider is wrong direction | Adv5 | Confirmed correct by architect ruling (provider = balance - price) |
| Pull path unverified public_key for ledger | Adv1 | Subsumed by F1 fix |
| Information disclosure through error logs | Adv5 | Logs are local, not network-exposed |
| CancelledError handling (Python <3.9) | Adv5 | Project requires Python 3.10+ |
